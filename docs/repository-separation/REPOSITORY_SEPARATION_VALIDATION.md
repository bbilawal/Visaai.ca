### A classification bug caught before it did damage

The first pass retained five files *inside* `docs/` purely because they were
named `README.md` or `AGENTS.md` — `docs/ai-case-engine/AGENTS.md`,
`docs/analytics/load-test/README.md`, and others. Reading them showed they are
ordinary documentation (a LangGraph node reference; a folder index), not control
files. The rule was corrected to "basename only matters *outside* `docs/`", and
four of the five moved.

The fifth, `docs/i18n/review/README.md`, is a genuine exception discovered the
same way: `scripts/i18n/build-review-package.mjs` hardcodes
`OUT_DIR = docs/i18n/review`, so the generator would recreate the directory
regardless — and VISAAIDocs commit `b551d5b` had already recorded the decision
that this package stays in the app repo. Retained, and re-verified after the
move by running `pnpm i18n:review`, which regenerated 14 locale CSVs + manifest
+ README for 732 keys.

## 4. Movement procedure (§8.6)

Executed strictly in order, with deletion last:

1. sha256 of every source
2. copy to destination (`shutil.copy2`, preserving mtime)
3. sha256 of every destination
4. **compare** — abort the whole operation on any mismatch
5. update references in code, CI and scripts
6. run builds and tests
7. re-verify all 255 destinations still present and byte-identical
8. `git rm` the originals
9. record `MOVE_VERIFIED` per row

No file was deleted before its copy was proven byte-identical, twice.

## 7. TEST-004 — one flaky test, recorded not dismissed

During the docs-absent run, `test/ai-agent/visa-resilience.spec.ts` failed once.

It then passed in **8 consecutive isolated runs** and **3 consecutive full-suite
runs**. The spec contains no timers, `Date.now`, `Promise.all` or retry logic,
so the cause is not obvious from the file, and it is **not reproducible**.

It is recorded as a flake with an unknown cause rather than written off as
noise. It is unrelated to this phase: the failure occurred with the docs repo
absent, but the spec reads no documentation, and the same run had already passed
in the full suite immediately before. Under the programme's own rule — every
flaky result needs a finding ID, owner and evidence — it is TEST-004, open.
